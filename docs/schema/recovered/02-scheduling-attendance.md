# 一、班表設計核心

班表不能只使用「星期一～星期日」作為唯一排班模型。

原因：像「做二休二」屬於循環週期，不會固定對應星期幾。

因此排班模型需同時支援：

- 固定週班
- 循環班，例如做二休二
- 輪班
- 零工／非固定班
- 假日班
- 中途調班
- 臨時異動

已討論的概念層級：

```text
班別／排班規則
        ↓
產生員工實際班表
        ↓
employee_schedules
```

原討論中曾使用 `schedule_templates` / 排班週期概念，但目前無法可靠恢復其完整正式表名與欄位，因此此處不宣告為最終 Schema。

# 二、`employee_schedules`

## 用途

保存員工「某一天實際被排到什麼班」，是後續出勤、請假、加班資格判斷的重要事實資料。

## 已恢復核心欄位方向

| 欄位 | 說明 |
|---|---|
| `id` | 主鍵 |
| `employee_id` | 員工 |
| `schedule_date` | 實際排班日期 |
| `shift / shift_id` | 當日班別；正式欄位名稱待繼續恢復 |
| `start_time` | 當日預定上班時間 |
| `end_time` | 當日預定下班時間 |
| `day_type_code` | 工作日／休息日／假日等班表性質；代碼細節待恢復 |
| `created_at` | 建立時間 |
| `updated_at` | 更新時間 |

> 上表只列目前能可靠還原的欄位方向；完整欄位與代碼仍待後續恢復。

## 核心規則

- `employee_schedules` 是「實際班表」，不是永久排班規則。
- 系統可以預先產生一段期間的員工班表。
- 歷史已產生班表不能因後續排班模板／規則修改而被覆蓋。
- 如果中途調班，必須保留原排班與異動歷史，不可無痕覆蓋。
- 員工請假不代表原班表消失；請假仍需對照原班表判斷應工作時間。
- 員工某日在其班表體系被定義為休假／假日，才可依相關規則判斷假日加班資格。

# 三、班表產生方式

## 固定週班

典型情況：週一～週五固定上班、週末休息。

這種可以用星期規則產生 `employee_schedules`。

## 循環班

例如：

```text
工作
工作
休息
休息
工作
工作
休息
休息
...
```

循環班必須用「週期位置」推進，不能硬塞進 7 天星期模型。

## 輪班

需要允許不同週期／日期使用不同班別，再落成每日 `employee_schedules`。

## 零工／非固定排班

沒有固定週班或長週期模板時，可直接排實際日期／時段。

# 四、調班／班表異動

## 已確認規則

排好班後仍可能中途調班。

```text
原實際班表
    ↓
發生調班
    ↓
建立異動
    ↓
形成新的有效班表狀態
```

歷史不可消失。

# 五、出勤／打卡

## `attendance_records`

### 用途

保存員工實際上下班打卡事件。

### 已恢復核心資料方向

| 欄位 | 說明 |
|---|---|
| `id` | 打卡紀錄 ID |
| `employee_id` | 員工 |
| `punch_type_code` | 上班／下班打卡類型 |
| `punched_at` | 實際打卡時間 |
| `latitude` | GPS 緯度，可空 |
| `longitude` | GPS 經度，可空 |
| `created_at` | 建立時間 |

## 已確認打卡規則

- 員工可以打上班卡。
- 必須先存在有效上班卡，才能打下班卡。
- 上班卡可以撤銷。
- 下班卡可以撤銷。
- GPS 可以記錄，但不是強制條件。
- 打卡與班表分開保存；實際打卡不改寫原始班表。

# 六、打卡撤銷

## 已確認規則

打錯卡時，員工可以自行撤銷上班或下班打卡。

撤銷不代表物理 DELETE 原紀錄。

```text
原打卡紀錄
    ↓
撤銷
    ↓
原始事實保留
```

因此系統必須保留：

- 原打卡
- 撤銷時間
- 撤銷狀態／原因（若有）

原討論中的撤銷資料究竟是同表狀態欄位或獨立事件表，目前完整 Schema 尚未可靠恢復，此處只鎖定業務規則。

# 七、忘打卡補登

## 已確認規則

忘記打卡不能直接修改原始打卡時間，需透過補登申請。

而且「上班卡」與「下班卡」是分開補登：

```text
忘記上班卡
→ 只申請補上班卡

忘記下班卡
→ 只申請補下班卡
```

不要求一次補成完整的一天。

補登需要申請／審核流程，核准後再形成有效出勤紀錄或補登結果。

目前原討論中的正式補登 Schema 名稱與完整欄位尚未可靠恢復，因此不自行建立猜測表名。

# 八、班表、出勤、請假、加班的相依關係

```text
排班規則／班表體系
        ↓
employee_schedules
        │
        ├──→ 出勤／打卡
        │
        ├──→ 請假：計算本來應工作多少時間
        │
        └──→ 加班：判斷當天是否具備加班資格
```

重要原則：

- 班表是「應該工作什麼時間」。
- 打卡是「實際什麼時間到／離開」。
- 請假是「原本應工作但合法免除工作」。
- 加班是「原班表以外、且符合申請／核准條件的工作」。

四者不能混成同一份資料。
